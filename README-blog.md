# Peco 的小小博客

访客入口：`https://peco.ink/blog/`。首页和公共导航中都有博客入口，首页会展示最近三篇已发布文章。

管理入口沿用原有规则：在博客地址后加 `?admin=原来的暗号`。如果已经在留言板地址中使用了同一参数，点击导航中的「博客」也会带入管理入口。请使用原来的值，不需要另设博客密码。

服务器验证暗号后会发放 12 小时的 HttpOnly、SameSite=Strict 管理会话，HTTPS 下启用 Secure。验证成功后清除地址栏里的 `admin` 参数；分享链接仅包含文章编号。退出管理会清除本浏览器的管理会话。

## 写作

- 管理模式下点击「写一篇」，填写标题、分类与可选摘要。
- 正文可以添加文字、小标题、引用和图片；各段可上移、下移、移除。
- 图片支持 JPG、PNG、WebP，每张原始文件最多 12 MB，每篇最多十二张。较大的图片会在浏览器中优化后上传，默认第一张图片为封面，也可以在编辑器中重新指定。
- 「存为草稿」保存到服务器，只有管理模式能读取；文章和关联图片发布前不对访客开放。
- 发布后的文章可以编辑、收回草稿或删除。编辑器检测版本冲突，避免旧标签页覆盖已经保存的新版本。
- 删除文章会同时移除本篇的留言、喜欢和不再被其他文章使用的配图。界面会先要求确认。

访客能阅读、点赞、留言与回复。留言使用原有 Turnstile 验证，保留原留言接口对作者昵称的保护；访客不能上传博客图片、写作、修改文章或删除内容。

## 数据与部署

继续使用现有 Cloudflare Pages 和 D1 `DB` 绑定，无需新增服务或绑定。首次访问博客接口会以 `CREATE TABLE IF NOT EXISTS` 创建 `blog_posts`、`blog_images`、`blog_post_images` 和相关索引，不修改原有表。

文章正文保存为受限的文字、标题、引用和图片结构，前端通过文本节点渲染，不执行文章内的 HTML。单篇最多五万字、八十段内容。博客图片存储在 D1 中，每张优化后的图片最多 1,200,000 字节，低于 D1 单行的大小限制。

点赞和评论沿用现有表，分别使用独立的 `blog_<文章编号>` 标识；原有首页、留言板、树洞和像素画板的数据保持原样。文章与图片由 Cloudflare 提供，无需本地聊天中转电脑开机。

相关文件：

- `blog/index.html`、`blog/blog.css`：界面与蓝黄主题。
- `blog/blog.js`、`blog/editor.js`、`blog/ui.js`：阅读、互动和编辑器。
- `home-blog.js`：首页最近文章。
- `functions/api/blog/[[path]].js`：文章、图片、互动和管理会话接口。
- `functions/_lib/blog-auth.js`、`blog-db.js`：身份校验、数据校验和数据库初始化。
- `functions/_lib/admin.js`：博客与留言板共用同一个管理员暗号。

## 现有管理员暗号

按当前要求保留了原有暗号。该值原本已写在公开 GitHub 源码中，知晓暗号的人也能进入管理模式，因此这套方法不能证明访问者就是站长本人。

如以后需要限制他人使用，应在 Cloudflare Pages 生产环境设置 Secret `ADMIN_TOKEN` 为新的私密值，并重新部署。该配置会同时作用于留言板和博客，入口形式仍为 `admin=...`；请同时更新自己的管理书签。旧值已在公开历史中，单纯从当前文件删除它无法撤销历史公开。

## 验证

`npm test` 包含基于真实 SQLite 的管理权限、草稿与图片访问边界、编辑冲突、点赞、评论和旧数据保留测试，以及原有聊天服务的回归测试。隔离的浏览器流程测试和本机预览数据保存在 Git 忽略的 `.bridge-local` 中，不会部署到正式网站。

Cloudflare 官方参考：[D1 类型转换与 BLOB](https://developers.cloudflare.com/d1/worker-api/)、[D1 大小限制](https://developers.cloudflare.com/d1/platform/limits/)。
